# 简序 · V2

将已有简历整理成可以独立分享的个人展示页。求职者上传文件或粘贴内容，核对系统提取的教育、实习、奖项与项目信息，预览后发布；HR 通过链接直接阅读，无需登录。

这是可本地运行、带后端与数据库的 V2 源码。首轮改进了简历提取准确性与字段原文联动核对；当前迭代继续加入自动保存草稿和更省步骤的核对操作。将服务部署到可访问的服务器后，独立分享链接才能供互联网上的其他人打开。

## 快速运行

需要 **Node.js 24 或更高版本**（使用内置 SQLite），以及随 Node.js 安装的 npm。

在项目文件夹打开终端：

```powershell
npm.cmd ci
npm.cmd start
```

macOS/Linux 可使用 `npm ci` 和 `npm start`。浏览器访问 **http://localhost:3000**。也可以在 Windows 双击 `start.cmd`，首次运行会安装依赖。

当前界面采用桌面浏览器布局，建议浏览器窗口宽度至少 **1200px**。手机和平板专用适配已移除，小屏设备会保留桌面布局，可能需要横向滚动。

无需填写任何模型密钥即可使用本地解析。首次使用请注册一个本地账号。演示简历中的院校、企业及赛事名称真实，人物与个人经历为模拟内容，不代表真实求职者。

## 使用流程

1. 注册或登录，进入「我的简历」。
2. 导入 PDF、DOCX、TXT，或直接粘贴简历文本；也可新建空白简历。
3. 点击输入框或旁边的「原文」，右侧定位并高亮对应内容；无法确定对应位置的字段会提示人工核对。
4. 检查后点击「确认并下一项」继续，也可只确认当前字段。在「核对范围」中选择全部待核对、需检查、修改后待核对或未定位原文，集中处理对应问题。
5. 多字段可通过「核对本段经历」集中检查：弹窗逐行列出当前内容和对应原文，确认后仅标记无异常且未修改的字段；有提醒、已修改或无法定位原文的字段保留为单独核对。
6. 补充缺失字段、调整内容和展示设置。停止修改约 1 秒后自动保存草稿，核对状态也随之保存；修改已确认字段后需要重新核对。顶部显示等待保存、正在保存、已保存或保存失败，仍可点击「保存草稿」立即保存。
7. 预览、发布并复制独立分享链接。自动或手动保存草稿都不会改变已发布内容；再次发布才更新公开版本，链接保持不变。
8. 下架后，原分享链接不可访问。公开页支持通过浏览器打印为 PDF。

在「展示设置」中，长按模块左侧的六点把手约 0.15 秒后拖动，可调整阅读顺序。松开确认后，移动的模块在新位置高亮 3 秒，模块名称加粗，便于确认排序结果；按 Esc 可取消拖动。也可通过「更多」选择目标位置，或聚焦把手后用空格/回车拾取、上下方向键移动、空格/回车确认。模块显示勾选独立保留。底部不再显示蓝色状态文字，读屏操作提示继续保留。顺序修改会自动保存到草稿，更新发布后才会影响 HR 展示页。

保存失败时，修改仍保留在当前页面，检查连接后点击「重试」或「保存草稿」。尚未保存就刷新或关闭页面时会出现浏览器离开提醒。此功能不提供跨刷新、关闭或重启的离线恢复；看到「草稿已保存」才表示修改已写入服务端。

## V2 本轮改进

- 更准确地区分多段教育与实习：同校不同学历、同公司不同周期、独立日期行、单独专业和岗位行。
- 支持常见年月、点号、斜杠及「至今」写法；修复 10–12 月截断问题。日期归属不明确时保留已有内容并提示核对。
- 分离同一行中的职责、成果与技术栈，保留多行描述并避免重复。
- 字段与原文联动：定位、高亮、具体缺项提示、逐项确认、待核对队列和进度。缺失或存在歧义的原文位置不会标成已准确匹配。
- 核对记录只保存在私人草稿。字段修改后，原确认失效；当前迭代会自动保存这些变化。
- 自动保存草稿：停止修改约 1 秒后保存，保存期间继续编辑会排队保存最新修改；显示保存状态和失败重试入口，发布仍需用户主动操作。
- 减少核对步骤：「确认并下一项」、四类待核对筛选，以及对照原文后确认本段无异常字段。系统找到原文不会自动等同于用户已确认。

## 完整功能

- 多用户注册登录、持久会话，用户之间的草稿相互隔离。
- SQLite 持久保存简历，重启服务后数据仍然存在。
- 真实文件文本提取：文字型 PDF、DOCX、UTF-8 TXT；单文件最多 8 MB；PDF 最多 12 页，提取文本最多 60,000 字符。
- 中文简历结构化解析：教育背景、实习/工作、荣誉奖项、项目经历、技能及基本资料。
- 字段级原文定位与高亮、待核对提示、确认并下一项、分类筛选、整段核对、可编辑字段、多条经历增删。
- 模块长按拖动排序、点击位置选择与键盘排序；模块显示、联系方式公开设置、实时预览和放大阅读。
- 自动保存与手动保存草稿、失败重试、未保存离开提醒；草稿与发布快照分离、稳定独立链接、更新发布、下架与删除。
- 桌面浏览器布局、键盘焦点、加载/失败/空态反馈、打印样式。
- 可选模型辅助解析；默认关闭，用户主动选择后才会将文本发送到所配置的服务。

## 解析范围与限制

本地模式使用文件文本提取与规则分类，不保证任意排版、任意语言都能一次识别准确。标准中文标题、较清晰的单栏简历是主要支持范围。复杂双栏、表格、缺失标题、同一行混合多个字段时，需要重点核对。

扫描件、图片式 PDF 和图片文件仍不支持 OCR；无法读到文字时会提示用户改用可复制文字的文件或粘贴文本。旧版 `.doc` 不支持，请先另存为 `.docx`。原文没有写出的学历、奖项级别、个人贡献和数字不会被有意补造，发布前仍需本人核对。

原始文件在解析后不作为附件长期保存；提取出的原文、字段来源位置和核对记录保存在私人草稿中，供本人核对。公开接口不返回原文、解析提示或核对记录。原文定位表示字段与导入文字的对应关系，不代表对经历真实性的验证。公开页的「打印 / 导出 PDF」生成的是展示版，而非原始文件下载。

账号用于基本访问控制，尚未接入邮件验证、密码找回或商业平台运营后台。请勿将演示账号密码用于其他服务。

## 配置

将 `.env.example` 复制为 `.env`，按需修改。不要将 `.env`、数据库或真实简历提交到代码仓库。

| 配置 | 用途 |
| --- | --- |
| `PORT` | 服务端口，默认 3000 |
| `HOST` | 监听地址，本地默认 127.0.0.1；容器/服务器使用 0.0.0.0 |
| `DATA_DIR` | 数据存储目录，默认项目下 data |
| `PUBLIC_BASE_URL` | 对外访问地址，例如 https://resume.example.com，用来生成分享链接 |
| `COOKIE_SECURE` | HTTPS 部署设为 true；普通 HTTP 本地开发保持 false |
| `AI_BASE_URL` | 可选的 Chat Completions 兼容服务基础地址，通常以 /v1 结尾 |
| `AI_API_KEY` | 可选服务密钥，仅保留在服务端 |
| `AI_MODEL` | 可选服务的模型名称 |

只有完整配置模型服务时，界面才提供模型辅助选项。用户未选择时，简历不会发送给模型服务。若模型调用失败，系统应回退到本地解析并提示，不影响后续人工编辑。自动测试不调用收费模型接口。

## 源码结构

```text
public/            原生前端、示例数据、简历渲染与样式
server/app.js      HTTP API、权限检查、文件导入、静态页面
server/store.js    SQLite 数据存储与发布快照
server/validation.js  输入结构校验与公开字段过滤
server/parser.js   简历分节、字段提取、可选模型辅助
server/provenance.js  字段原文位置与核对记录协调
server/extract.js  PDF / DOCX / TXT 文本读取
public/review.js   字段核对状态与高亮范围
public/autosave.js 草稿自动保存调度与重试
server/index.js    服务启动入口
tests/             自动化测试与虚构测试样本
samples/           可自行导入的虚构示例简历
docs/              数据接口约定与验证说明
data/              运行时数据（自动生成，不包含在交付包中）
```

## 部署与分享

本地 `localhost` 链接只对当前电脑有意义。局域网访问可将 `HOST` 设为 `0.0.0.0`，并使用该电脑的局域网地址；外网访问应部署到自己的服务器并配置 HTTPS 和 `PUBLIC_BASE_URL`。

项目提供可选 Docker 配置：

```sh
docker compose up --build -d
```

默认映射 3000 端口，数据写入持久卷。首次部署请修改 `.env` 的对外地址；正式 HTTPS 服务由反向代理提供，且需开启安全 Cookie。备份数据库前停止写入，或使用 SQLite 的备份机制，不要只复制活跃 WAL 模式下的主数据库文件。
