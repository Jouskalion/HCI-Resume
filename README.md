# 简序 · V1

将已有简历整理成可以独立分享的个人展示页。求职者上传文件或粘贴内容，核对系统提取的教育、实习、奖项与项目信息，预览后发布；HR 通过链接直接阅读，无需登录。

这是可本地运行、带后端与数据库的完整 V1 源码。它不是已经开通公网域名的在线服务。将服务部署到可访问的服务器后，独立分享链接才能供互联网上的其他人打开。

## 快速运行

需要 **Node.js 24 或更高版本**（使用内置 SQLite），以及随 Node.js 安装的 npm。

在项目文件夹打开终端：

```powershell
npm.cmd ci
npm.cmd start
```

macOS/Linux 可使用 `npm ci` 和 `npm start`。浏览器访问 **http://localhost:3000**。也可以在 Windows 双击 `start.cmd`，首次运行会安装依赖。

当前界面采用桌面浏览器布局，建议浏览器窗口宽度至少 **1200px**。手机和平板专用适配已移除，小屏设备会保留桌面布局，可能需要横向滚动。

无需填写任何模型密钥即可使用本地解析。首次使用请注册一个本地账号。演示简历中的院校、企业及赛事名称真实，人物与个人经历为模拟内容，不代表真实求职者。

## 使用流程

1. 注册或登录，进入「我的简历」。
2. 导入 PDF、DOCX、TXT，或直接粘贴简历文本；也可新建空白简历。
3. 在编辑器逐项核对，补充缺失字段、修改分类、调整模块顺序和公开范围。
4. 保存草稿并查看预览，确认后发布。
5. 复制独立分享链接。保存草稿不会改变已发布内容；再次发布才更新公开版本，链接保持不变。
6. 下架后，原分享链接不可访问。公开页支持通过浏览器打印为 PDF。

在「展示设置」中，长按模块左侧的六点把手约 0.15 秒后拖动，可调整阅读顺序。松开确认后，移动的模块在新位置高亮 3 秒，模块名称加粗，便于确认排序结果；按 Esc 可取消拖动。也可通过「更多」选择目标位置，或聚焦把手后用空格/回车拾取、上下方向键移动、空格/回车确认。模块显示勾选独立保留。底部不再显示蓝色状态文字，读屏操作提示继续保留。修改顺序后请保存草稿，更新发布后才会影响 HR 展示页。

## V1 功能

- 多用户注册登录、持久会话，用户之间的草稿相互隔离。
- SQLite 持久保存简历，重启服务后数据仍然存在。
- 真实文件文本提取：文字型 PDF、DOCX、UTF-8 TXT；单文件最多 8 MB；PDF 最多 12 页，提取文本最多 60,000 字符。
- 中文简历结构化解析：教育背景、实习/工作、荣誉奖项、项目经历、技能及基本资料。
- 解析原文对照、待核对提示、可编辑字段、多条经历增删。
- 模块长按拖动排序、点击位置选择与键盘排序；模块显示、联系方式公开设置、实时预览和放大阅读。
- 草稿与发布快照分离、稳定独立链接、更新发布、下架与删除。
- 桌面浏览器布局、键盘焦点、加载/失败/空态反馈、打印样式。
- 可选模型辅助解析；默认关闭，用户主动选择后才会将文本发送到所配置的服务。

## 解析范围与限制

本地模式使用文件文本提取与规则分类，不保证任意排版、任意语言都能一次识别准确。标准中文标题、较清晰的单栏简历是主要支持范围。复杂双栏、表格、缺失标题、同一行混合多个字段时，需要重点核对。

扫描件、图片式 PDF 和图片文件不在 V1 的 OCR 支持范围内；无法读到文字时会提示用户改用可复制文字的文件或粘贴文本。旧版 `.doc` 不支持，请先另存为 `.docx`。原文没有写出的学历、奖项级别、个人贡献和数字不会被有意补造，发布前仍需本人核对。

原始文件在解析后不作为附件长期保存；提取出的原文保存在私人草稿中，供本人核对。公开接口不返回原文和解析提示。公开页的「打印 / 导出 PDF」生成的是展示版，而非原始文件下载。

账号用于 V1 的基本访问控制，尚未接入邮件验证、密码找回或商业平台运营后台。请勿将演示账号密码用于其他服务。

## 配置

将 `.env.example` 复制为 `.env`，按需修改。不要将 `.env`、数据库或真实简历提交到代码仓库。

| 配置 | 用途 |
| --- | --- |
| `PORT` | 服务端口，默认 3000 |
| `HOST` | 监听地址，本地默认 127.0.0.1；容器/服务器使用 0.0.0.0 |
| `DATA_DIR` | 数据存储目录，默认项目下 data |
| `PUBLIC_BASE_URL` | 对外访问地址，例如 https://resume.example.com，用来生成分享链接 |
| `COOKIE_SECURE` | HTTPS 部署设为 true；普通 HTTP 本地开发保持 false |
| `AI_BASE_URL` | 可选的 Chat Completions 兼容服务基础地址，通常以 /v1 结尾 |
| `AI_API_KEY` | 可选服务密钥，仅保留在服务端 |
| `AI_MODEL` | 可选服务的模型名称 |

只有完整配置模型服务时，界面才提供模型辅助选项。用户未选择时，简历不会发送给模型服务。若模型调用失败，系统应回退到本地解析并提示，不影响后续人工编辑。V1 的自动测试不调用收费模型接口。

## 源码结构

```text
public/            原生前端、示例数据、简历渲染与样式
server/app.js      HTTP API、权限检查、文件导入、静态页面
server/store.js    SQLite 数据存储与发布快照
server/validation.js  输入结构校验与公开字段过滤
server/parser.js   简历分节、字段提取、可选模型辅助
server/extract.js  PDF / DOCX / TXT 文本读取
server/index.js    服务启动入口
tests/             自动化测试与虚构测试样本
samples/           可自行导入的虚构示例简历
docs/              数据接口约定与验证说明
data/              运行时数据（自动生成，不包含在交付包中）
```

## 部署与分享

本地 `localhost` 链接只对当前电脑有意义。局域网访问可将 `HOST` 设为 `0.0.0.0`，并使用该电脑的局域网地址；外网访问应部署到自己的服务器并配置 HTTPS 和 `PUBLIC_BASE_URL`。

项目提供可选 Docker 配置：

```sh
docker compose up --build -d
```

默认映射 3000 端口，数据写入持久卷。首次部署请修改 `.env` 的对外地址；正式 HTTPS 服务由反向代理提供，且需开启安全 Cookie。备份数据库前停止写入，或使用 SQLite 的备份机制，不要只复制活跃 WAL 模式下的主数据库文件。
